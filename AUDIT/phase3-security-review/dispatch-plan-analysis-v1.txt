Independent T000009 plan analysis by Phase3-Security-Reviewer, S000011, 2026-10-13.
Target D000010-A001, local provider-neutral fake dispatch receipt boundary.

Approve only as a bounded local fake contract. A request parser must read a bounded byte sequence once, require strict UTF-8 canonical JSON with duplicate-key/nonfinite rejection and exact top-level fields/types; provider and adapter values must be an allowlisted `fake`, operation must be inert data rather than a command, and input must remain bounded canonical JSON. Unknown providers, malformed/bool/noncanonical/oversized requests fail before output creation or project-ledger mutation.

The fake implementation must never invoke shell, subprocess, network, credential lookup or dynamic imports. Test with actual monkeypatch guards around subprocess/socket/credential access and inspect the implementation imports. Provider/adapter labels are declarations, not authenticated identity; docs and receipts must not imply Codex/Claude/Cursor/Qoder/ZCode invocation or provider compatibility. Response bytes should be deterministic from canonical request bytes and bounded; no private prompt/input content should be copied into ledger state.

Receipt publication is an integrity boundary. Require an external project-relative-safe path with no absolute/parent/symlink/metadata escape, exclusive create semantics, and flushed bytes plus parent-directory durability before success. Existing receipt/output and symlink/ancestor races must fail without replacement. A failed request, unknown provider, response or publication step must leave no published receipt and no ledger event. The implementation must not call the normal ledger mutation path for dispatch; separately registering a receipt as ordinary evidence remains explicit.

Receipt schema must be strict canonical bounded JSON with exact fields, provider/adapter allowlist, request hash, response hash, status, operation and observation timestamps. Verify re-reads bounded request and receipt bytes, checks current request hash and exact response/hash binding, rejects tampering, drift, changed provider/adapter labels, unknown fields, duplicate/nonfinite values, and malformed timestamps. A receipt authenticates only observed local fake bytes; timestamps are observations, not trusted freshness. If request drift is expected after dispatch, verification must report it rather than substitute the old bytes from an unbound path. Bind the request path/hash or include immutable request bytes as an external artifact without copying sensitive content to ledger.

Input and output path handling must reject project metadata/generated paths, symlinks and `..`; receipt parent creation must not silently follow a symlink. Canonical request files may be ordinary evidence but their live and snapshot gates remain separate. Atomic temp write followed by replacement is insufficient for immutable output if an attacker can pre-create or race the destination; exclusive directory/file publication and no-overwrite tests are required.

Required evidence before plan approval: real CLI canonical/binary request and deterministic response; malformed duplicate/noncanonical/bool/oversized/unknown-provider failures; request drift and receipt tamper rejection; provider/adapter spoof rejection; output absolute/parent/symlink/overwrite failures; subprocess/socket/credential guard proving no hidden execution; failed dispatch no receipt and unchanged ledger; ordinary evidence registration; full regression and scaffold. Preserve any incorrect harness as a failed evidence path rather than silently replacing it.

Accepted limits: local operator filesystem custody and arbitrary OS writers, no real provider invocation or network identity, no remote receipt durability, retries/rate limits/distributed idempotency, and no claim of model identity, authorization, delivery or scientific quality.
