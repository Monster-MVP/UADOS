T000008 pre-debate clarifications, 2026-10-13.
Capture and validate the entire evidence_files argument batch before any snapshot publication when at least one opt-in manifest is registered. This includes ordinary top-level files in that batch within the same aggregate ingestion bound; ordinary batches without a manifest retain existing behavior. Registration hashes and snapshots the captured bytes once; no filesystem-wide atomicity is asserted.
At validation, reconstruct each expected transitive closure exclusively from its immutable archived manifest bytes, compare the exact stored path/hash/byte bindings, and validate every promised member snapshot. Never resolve an old declaration from a newer live manifest. Current live-file checks remain separate.
Actual SHA256-consistent cyclic manifest graphs cannot ordinarily be constructed without a fixed-point/collision; test cycle guard with explicitly identified capture/parser injection, and use real bytes for acyclic DAG, tamper, export and gate cases. Do not report injection as a cryptographic cycle construction.
All graph node/manifest/aggregate bounds apply before unbounded reads, using metadata plus bounded reads to reject files that grow. Shared identical nodes are deduplicated; same canonical path with different hash/bytes/kind is a conflict. Error before commit produces no event; publication after valid graph may leave harmless orphan snapshots on later disk/commit failure, never a partial evidence record.
Historical archive corruption or omitted/extra/malformed closure is an integrity error, not a harmless historical live-path drift. Full-state ledger, schema and protocol migrations are excluded. Matching newer runtime is required to enforce optional dependency metadata; no automatic downgrade compatibility is claimed.
