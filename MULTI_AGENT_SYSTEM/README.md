# Multi-agent collaboration

UADOS coordinates contributors through durable tasks, scoped ownership, review records and session handovers. It does not need a particular model provider or orchestration service. The human or agent environment chooses how to start independent contributors; each contributor uses the same project record.

The lifecycle authority is `MASTER_AGENT_WORKFLOW.md`. Read `roles.md` for responsibilities and `review_protocol.md` for substantive review. Protocol-2 major work uses `role_generator.md`, `agent_selection.md`, `debate_protocol.md` and `consensus_protocol.md`. Generated `role_plans.md` and root `CONSENSUS_DECISION.md` record the current plan/debates. A team can combine roles transparently; role count does not replace the independent reviewer quorum.

Before assigning work, make a task with a concrete outcome, relevant paths, risk and dependencies. Contributors inspect current context and claim their tasks. Keep parallel scopes disjoint where possible. Active claims with overlapping declared scopes are rejected; scope-less tasks cannot provide file-level coordination. A task lease is a recorded ownership mechanism rather than an operating-system access restriction.

Communication that changes project direction must become a decision, task or note. A reviewer should leave an evidence-backed challenge instead of an untraceable approval in chat. Before a contributor leaves, close the session with current findings and a usable next step.

The team remains responsible for real independence. Creating several labels in one process does not satisfy adversarial review. Record actual reviewer ownership, inspected artifacts and assumptions challenged so a human can assess quality. UADOS selects registered declared capabilities and exports agent-neutral dispatch packets; an authorized host supplies actual independent contributors. It does not call model providers automatically.
