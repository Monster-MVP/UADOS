# Consensus and dissent

Lifecycle authority: [MASTER_AGENT_WORKFLOW.md](../MASTER_AGENT_WORKFLOW.md). `CONSENSUS_DECISION.md` is generated from recorded debates. Do not create a manually approved substitute.

A consensus identifies the selected Round-1 analysis, selected approach, rejected alternatives and reasons, remaining risks, participants, role ownership, challenges, votes and evidence. The selected approach must correspond to a real analysis in that debate. Record unresolved objections; a report that drops dissent cannot justify the master's review gate.

Consensus requires complete ordered rounds and current bound inputs. Consensus records independent plan/result approvals from eligible reviewer votes, bound to the current task fingerprint. A manually written consensus report does not substitute for those governed approvals. At least two eligible independent reviewers are required for a protocol-2 major debate, even when one reviewer covers several roles. The actual human/model independence remains a team responsibility.

A requested change prevents treating the debate as approved until the required renewed process resolves it. Do not relabel an implementer, replace a participant or summarize away an objection to manufacture approval. Keep earlier debate outcomes visible when a new debate is opened. Changed task, policy, scope, source, assignments, capabilities or evidence requires the CLI's staleness checks and renewed review.

Remaining risks need an explicit disposition: accepted within authority, validated, blocked pending evidence, or assigned follow-up. Consensus is a traceable local decision, not distributed fault-tolerant consensus or a guarantee of a correct technical/scientific conclusion.
