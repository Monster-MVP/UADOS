# Task execution protocol

Authority: [master workflow, sections 2–4](../MASTER_AGENT_WORKFLOW.md#2-define-and-review-owned-work). Use this worksheet to assemble the task packet; the task's recorded protocol controls its gates.

| Stage | Concrete record or outcome |
| --- | --- |
| Task definition | Observable outcome, acceptance criteria, scopes, dependencies and existing-work inspection |
| Risk assessment | Consequence of failure and why routine/major classification fits |
| Implementation plan | Proposed steps, alternatives, recovery and meaningful validation; readable supporting evidence |
| Multi-agent review | Independent challenge; protocol-2 major role coverage, debate rounds and consensus |
| Execution | Claimed ownership and coherent maintained implementation |
| Validation | Executed commands/procedures, inputs, environment, failures and result evidence |
| Documentation update | Architecture, rationale, lessons and acceptance gaps in their proper maintained/ledger records |
| Final audit | Current consistency result and unresolved findings; current major result approvals before completion |

Review changes with the [debate protocol](../MULTI_AGENT_SYSTEM/debate_protocol.md) and [change policy](../CHANGE_REQUESTS/CHANGE_POLICY.md). A new task plan is a durable record, not a chat-only promise. Keep validation evidence outside generated files and preserve original failures. When a resource or ownership conflict blocks work, record the actual issue and a specific recovery action rather than lowering risk or inventing success.
