# Session handover preparation

- Closing session / contributor:
- Tasks and experiments affected:
- Relevant revision and evidence paths:

## Completed and validated

State what changed and why. For each important result, include the check or experiment and its artifact. Identify whether a result is observed, inferred or still unverified.

## Current stopping point

Describe the actual state of incomplete work: edited paths, partial outputs, active task ownership, unresolved review and resource availability. The next contributor should not need access to this conversation.

## Blockers and risks

| Issue | Why it blocks or matters | Evidence | Recovery / decision owner |
| --- | --- | --- | --- |
| | | | |

## Failed approaches

Preserve command/configuration, observed failure, attempted mitigation and reason not to repeat blindly. A valid negative result should be described as a result, not discarded as an execution failure.

## Next actions

Order concrete actions. For each, include task ID, relevant paths, expected outcome and dependency or authorization requirement. Start with the action that resolves the current stopping point.

Close the session with `session close`, passing the summary and applicable next/blocker/failed fields. The CLI generates `SESSION_HANDOVER.md`; do not replace it with this template by hand. Store longer supporting detail in a maintained note and reference its path.
