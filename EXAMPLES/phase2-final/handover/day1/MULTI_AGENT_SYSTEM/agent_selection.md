# Capability-based agent selection

Lifecycle authority: [MASTER_AGENT_WORKFLOW.md](../MASTER_AGENT_WORKFLOW.md). Register stable contributor identity, client/provider metadata if known and declared capabilities before assigning generated roles. Do not claim a capability because a model's marketing label implies it.

Match each role's required capabilities to registered declarations. Explain assignments and uncovered requirements. Implementation and review ownership must remain visible when several roles are assigned to one person/model. Task authors and current/past implementers are ineligible as independent reviewers; handover or renaming does not erase that history.

Before debate, verify full role coverage and the master's independent reviewer quorum. Freeze assignments, participant identities and capabilities in the debate input snapshot. Changes to task/policy/source/evidence, live assignments or capabilities can invalidate the debate; restart or renew it using the CLI's current controls.

The dispatch packet is provider-neutral JSON containing assignments, instructions, task/context and evidence references. It can be delivered by an authorized host to independent contributors. UADOS does not call paid APIs, provision credentials, spawn commercial clients or authenticate that contributors are different models. Actual dispatch, independence and cost authorization belong to the host/team.
