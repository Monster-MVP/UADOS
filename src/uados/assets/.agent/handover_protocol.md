# Agent handover protocol

Authority: [master workflow, section 6](../MASTER_AGENT_WORKFLOW.md#6-close-with-a-usable-handover). `SESSION_HANDOVER.md` is generated by session closure; this worksheet is preparation material, not an alternative register.

Before closing, assemble current status, completed work with validation, remaining task IDs, known problems, important decision IDs, rejected approaches and recommended next actions. Include paths, exact commands and access/environment constraints needed by a contributor who cannot read the old chat. Distinguish done, submitted for review, blocked and unvalidated work.

Use `session close` with the concise summary and actionable next steps; include actual blockers and failed approaches. Check generated handover and audit. Preserve unfinished implementation artifacts and contributor history. The incoming agent checks the ledger, task leases, evidence fingerprints and resource availability, starts its own stable session and uses the master's context procedure.

A scenario labeled “Day 1 Claude Code → Day 30 Codex” may use logical day labels to test recovery. Such labels do not establish 30 elapsed days or actual commercial-client invocation. Report the simulation method and invocation evidence separately.
